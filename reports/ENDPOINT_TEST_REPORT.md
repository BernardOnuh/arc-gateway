## 7. Observations

1. Chains, RPCs and ERC-20 addresses serve real, on-chain-verified data (see sections 1–2).
2. Fee math verified end-to-end: fee = amountIn × 10 / 10000, net = amountIn − fee, matches exactly (section 3).
3. Token resolution accepts both real addresses and symbols interchangeably.
4. Error handling returns the expected status codes; auth is enforced in a pre-validation onRequest hook, so any unauthenticated request returns 401 even with an invalid body (section 4).
5. Intent submission is idempotent per quoteId and the status lifecycle progresses ORIGIN_CONFIRMED → FILLED → EXECUTED_ON_ARC with originTx/destTx recorded.
6. **Arc decimals caveat:** chain-level native gas reports 18 decimals while the USDC ERC-20 interface reports 6. Quotes use the 6-decimal token amount.
7. **Still simulated:** the actual fill price, the origin-chain relay transaction, and Arc settlement. Real `estimatedOut`/`minOut` require a real quote/solver source; `unsignedTx` and submitted intents are placeholders.
8. **Business self-serve:** `POST /v1/partners` provisions a business (api key shown once, `feeBps=10` default). Customers registered per business expect `customerId` on quotes; `GET /v1/ledger` reports fees earned, per customer. Legacy keys (no partner) keep working for quotes but cannot use customers/ledger.
